You are a senior Python full-stack developer and QA automation engineer.

Build a complete, production-quality LOCAL WEB APPLICATION called:

"QA Test Case Document Generator"

The application is intended for QA testers who maintain test case designs in Excel and need to automatically generate professionally formatted Microsoft Word test-case documents.

IMPORTANT:
- This is a LOCAL application.
- It must run on Windows.
- No cloud services.
- No external database.
- No authentication/login.
- No internet connection should be required while using the application.
- Keep the architecture lightweight and maintainable.
- Do NOT use React, Angular, Vue, Node.js, Docker, or any heavy frontend framework.
- Use Python Flask for the backend.
- Use HTML, CSS and vanilla JavaScript for the frontend.
- Use openpyxl for Excel processing.
- Use python-docx for Word document generation.
- Use Python's zipfile module for ZIP generation.

==================================================
2. MAIN USER WORKFLOW
==================================================

The workflow should be:

1. User starts the application using start.bat.
2. Flask server starts locally.
3. Browser automatically opens:
   http://127.0.0.1:5000
4. User uploads an Excel test case design file.
5. Application validates the Excel headers.
6. Application reads only the required columns.
7. Application identifies individual TestCaseId groups.
8. Application displays all detected test cases.
9. User can select/deselect test cases.
10. User clicks "Generate Word Documents".
11. Application generates one DOCX file per TestCaseId.
12. Each test case is formatted professionally.
13. Every test step starts on a NEW PAGE.
14. Each step contains a clearly visible screenshot placeholder.
15. Application shows generation progress.
16. When complete, user can download:
    - individual DOCX files
    - OR all generated documents as a ZIP file.

==================================================
3. REQUIRED EXCEL COLUMNS
==================================================

ONLY these 9 Excel columns should be processed:

1. Priority
2. TestCaseId
3. PreCondition
4. TestCaseSummary
5. TestCaseDescription
6. Step Name
7. Test Step
8. Data
9. Expected Result

Ignore all other Excel columns.

IMPORTANT:
Do NOT depend on Excel column letters.

Find columns using their HEADER NAMES.

For example, if TestCaseId is in column J today and column C tomorrow, the application must still work.

Header matching should be reasonably tolerant of:
- leading/trailing spaces
- different capitalization

For example:
"TestCaseId"
"Test Case ID"
"testcaseid"

can optionally be normalized if practical.

The application must clearly report missing required columns.

Example:

✓ TestCaseDescription
✓ Step Name
✓ Test Step
✓ Data

Please correct the Excel file and upload it again.

==================================================
4. EXCEL DATA STRUCTURE
==================================================

The Excel file contains multiple rows belonging to the same TestCaseId.

Example:

Priority | TestCaseId | PreCondition | TestCaseSummary | TestCaseDescription | Step Name | Test Step | Data | Expected Result

High | TC-01 | User logged in | Claims validation | Verify claims... | 1 | Login to portal | Provider credentials | Dashboard displayed
     |       |                |                 |                  | 2 | Navigate to Message Center | Valid criteria | Search page displayed
     |       |                |                 |                  | 3 | Locate Claims details | | Header displayed
     |       |                |                 |                  | 4 | Click expand | | Section expands

High | TC-02 | User logged in | Another test | Verify... | 1 | Open page | URL | Page displayed
     |       |                |                 |          | 2 | Inspect header | | Header correct

The TestCaseId, Priority, PreCondition, TestCaseSummary and TestCaseDescription may only be populated on the first row of a test case.

The application must propagate/use the first non-empty value for the test-case-level fields.

A new TestCaseId indicates the start of a new test case.

All subsequent rows until the next TestCaseId belong to the previous test case.
